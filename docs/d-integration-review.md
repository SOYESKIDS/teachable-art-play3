### 섹션 15/15 가 뜻하는 것

  아니라 원문에 없는 것이고, 화면이 그 이유를 적는다.
- 17~24주 현장 난이도표 — 3권에는 이 표가 없다. `adaptations: null`.

## 4. 자료 등록 상태 — 조회 불가

| 항목 | 상태 |
|---|---|
| 자료 등록 건수 | **확인 못 함** |
| 실제 파일 열림·재생 | **확인 안 함** |

이 작업 트리에 Supabase 환경변수가 없다. `lesson_assets` 를 읽을 수 없어
등록 건수를 셀 수 없다. 화면은 이 상태를 숨기지 않고 **「확인 불가」**로 구분해 그린다.

화면이 구분하는 세 가지 — 섞으면 안 된다.

1. **차시 미연결** — `curriculum_lessons` 에 그 주차 차시가 없다
2. **미등록** — 차시는 있는데 `lesson_assets` 행이 없다
3. **확인 불가** — 조회 자체를 못 했다

또한 **경로 등록 ≠ 재생 성공**이다. `storage_path`·`external_url` 이 있다는 것은
파일이 열린다는 뜻이 아니다. 화면에 그 문구를 고정해 뒀다
(`ASSET_ACCESS_NOTE`). 실제 접근·재생 확인은 Preview 환경에서 해야 한다.

프로그램별 집계도 주의한다. 한 프로그램의 파일이 다른 프로그램의 누락을 가리지 않도록
**프로그램 · 차시 · 자료 종류**별로 나눠 세고 전체 합계는 따로 표시한다.

## 7. DB 연결(E단계)에 남은 일

지금 24주 콘텐츠는 **코드 안 fixture** 다. `week-source.ts` 는 Supabase 를 읽지 않는다.
연결하려면 아래가 필요하다.

### 7-1. 스키마가 지금 구조를 담지 못한다 — 가장 큰 항목

`lesson_sections` 는 이렇게 생겼다.

```
lesson_id · section_code (s1~s15) · body text (≤10000) · source_ref
```

**평문 한 덩어리**다. 그런데 전사본은 구조를 갖고 있다.

| 담지 못하는 것 | 지금 타입 | 왜 평문으로 못 미루나 |
|---|---|---|
| 표의 열 제목과 행 | `SourceTable { columns, rows }` | 권마다 열 제목이 다르고 뜻도 다르다. 평문으로 합치면 14번 가운데 칸이 무엇인지 사라진다 |
| 묶음 소제목 | `stepsLabel` · `noticeLabel` · `cautionsLabel` · `recordExampleLabel` · `closingLineLabel` | 주차마다 달라 화면이 고정할 수 없다 |
| 「원문에 없다」 | `null` vs `[]` | 평문에서는 빈 문자열과 구분되지 않는다 |
| 핵심활동과 미술이 같은 활동 | `sameAsCoreActivity` | 시간 중복 계산을 막는 표시다 |
| 가정연계 미정 | `status: "undecided"` | 발행을 막는 상태값이다 |

→ **필요한 일:** `lesson_sections.body_json jsonb` 를 더하거나, 표를 담을
`lesson_section_tables` 를 따로 두는 설계 결정. 지금 `body` 를 그대로 쓰면
전사 과정에서 되살린 구조가 다시 사라진다.

### 7-2. 표 자체가 없는 것

| 필요한 것 | 지금 | 비고 |
|---|---|---|
| 교실 화면 장면 | **표 없음** | 24주 236개 장면. `sceneNo` · `sceneType` · `kidText` · `stageLabel` · `teacherNote` · `sourceRef` · `baseSeconds` |
| 전사 주의 기록 | **표 없음** | 168건. `section` · `page` · `issue` · `category` · `status` · `evidence` |
| 본사 결정 | **표 없음** | 3건. 결정 이력(누가·언제·무엇으로)이 남아야 한다 |
| 원문 출처(해시) | `source_ref text` 만 | 지금은 `guide-sources.ts` 가 파일명·SHA-256·쪽수를 들고 있다 |

### 7-3. 발행 판정을 서버로 옮기는 일

지금 `assertPublishable(status, unresolvedNoteCount)` 는 **인자를 받는다**.
E단계에서는 서버가 **신뢰할 수 있는 저장 데이터에서 직접 조회**한 뒤 판정해야 한다.

```
status            ← curriculum_lessons.status (또는 주차 상태 표)
unresolvedCount   ← select count(*) where status = 'unresolved'
```

클라이언트가 보낸 값을 믿으면 미해결이 남은 주차도 발행된다.
현재 함수는 기본값 없이 필수 인자이고, 정수가 아니면 `TypeError` 를 던진다 —
「세지 않은 상태로 판정」을 막기 위해서다. 이 성질을 서버 조회로 옮길 때도 유지한다.
